# X3DP 転送プロトコル (v1)

スマホ(アプリ) → X3(ファーム) へ 1 フレームを送る仕様。全フィールド**リトルエンディアン**。

## フレーム

```
offset  size  field
0       4     magic      "X3DP" (ASCII)
4       1     version    1
5       1     mode       0 = 1bit, 1 = 2bpp(4階調)
6       2     width      792  (パネルの物理幅。論理528x792を90度回した形)
8       2     height     528
10      4     seq        下位24bit=連番, 上位8bit=フラグ
14      4     length     ペイロード長 (1bit = 52272, 2bpp = 104544)
18      4     crc32      ペイロードの CRC32 (zlib)
22      ...   payload
```

- 1bit ペイロード: `stride = 99` バイト/行 × 528 行、row-major、**MSB first、bit1 = 白**
- 2bpp ペイロード: `(792*528+3)/4 = 104544` バイト、row-major、4px/byte、`0=白 1=濃灰 2=薄灰 3=黒`
- パネルの物理レイアウトは **792×528**。論理 528×792 の `(x, y)` は `px = y, py = 527 - x`
  (PIL の `Image.ROTATE_90` と一致)。**回転は送信側で行う**。ファームは受け取った
  バイト列を `renderer.getFrameBuffer()` へ `memcpy` するだけです。

## トランスポート

### BLE (既定)

- GATT は **Nordic UART Service 互換**
  - service `6E400001-B5A3-F393-E0A9-E50E24DCCA9E`
  - RX (write / write-no-response) `6E400002-...` ← フレームを流し込む
  - TX (notify) `6E400003-...` → verb / 再送要求
- MTU 517 を要求。1 回の書き込みは **244 バイト以下**(超えると断片化して受信溢れします)
- ボンディング有効(Just Works)。Smart Lock の「信頼できるデバイス」に登録して
  画面ロック解除を維持する用途を想定
- 広告名は `X3DP-<MAC>`(MAC は Wi-Fi を止める前に読む必要があります)

### Wi-Fi (TCP 5283 / UDP 5284)

- 自動検出: UDP 5284 へ `X3DP?` を送ると `X3DP!<port>` が返る
- フレームは TCP 5283 へそのまま流す
- ソケットは Wi-Fi の `Network` に bind する(VPN 迂回)

## 制御バイト(スマホ → X3)

| byte | 意味 |
| --- | --- |
| `K` (0x4B) | 準備完了。受信パーサの**ヘッダ先頭でのみ**有効。受けた瞬間に X3 は `W` を返す |

## verb(X3 → スマホ)

| byte | 意味 |
| --- | --- |
| `W` (0x57) | 待機/送ってください |
| `N` (0x4E) | 次へ |
| `P` (0x50) | 前へ |
| `R` (0x52) | 再送要求(受信中に溢れた / リフレッシュ中だったので破棄した) |
| `S` (0x53) | 停止/その他 |
| `0x10+id` | カスタムアクション |

## 整合性のルール

- X3 はリフレッシュ中(および直後)に届いたフレームを丸ごと捨て、落ち着いてから `R` を送ります。
  アプリは直前のパケットを保持して再送します(概ね 2 秒以内に数回で打ち切り)。
- ヘッダ長は **22 バイトで凍結**。フラグを増やしたい場合は `seq` の上位バイトに詰めてください
  (長さを変えると旧クライアントが「送信成功」を出したまま X3 が永久待ちになります)。
